# ローカル専用：Firebase終了失敗と再試行の限定検証

MANUAL-AUTH-HARNESS-01：この画面は、実アプリと同じ認証サービスと実Firebase SDKを使い、Googleアカウント本人による選択後、Firebaseの `beforeAuthStateChanged` でログアウトを人工的に一度だけ阻止する。自然発生したGoogle障害や過去のiPhoneエラーを再現したものではなく、管理画面UI・GAS・Calendarの動作確認でもない。Google本人認証は実サービスにアクセスする。検証用会社アカウントのGoogle選択は本人が行う。

MANUAL-AUTH-HARNESS-02：PCの別ブラウザープロファイルまたは専用セッションを使用し、ブラウザー内の他のタブの認証状態と混同しない。テスト用アカウントがFirebaseで既に利用済みであることを確認する。誤ったアカウントの選択はFirebase Authenticationに新しいユーザーを作成する可能性がある。ハーネスは初回選択が会社アカウントかどうかを自動判定しない。本人が選択画面で確認する。

MANUAL-AUTH-HARNESS-03：実行は検証担当者が `npm run dev -- --host 127.0.0.1 --port 4197 --strictPort` とし、同じPCの `http://localhost:4197/tests/manual-auth-signout/` を開く。localhost以外では画面を無効にする。Viteはloopbackに限定し、テスト画面を公開・配備しない。この入口は通常のプロダクションビルド対象ではない。Firebase側のlocalhost認可がなければ設定を変更せず、未実施として記録する。

MANUAL-AUTH-HARNESS-04：画面の順番に、①準備後に会社の検証用Googleアカウントを本人が選択、②人工失敗を設定、③ログアウトを試行、④「人工的な終了失敗」かつ旧セッション取得拒否の表示を確認、⑤終了処理を再試行しFirebaseの現在ユーザーが空になった表示を確認、⑥同じアカウントを本人が再選択、⑦通常ログアウトを実行する。⑦の終了表示まで確認して専用タブを閉じる。

MANUAL-AUTH-HARNESS-05：失敗、誤ったアカウント、または中断時は「通常ログアウトして終了」で注入フックを解除し、終了したことを確認する。終了できない場合は専用タブを閉じ、結果を未確認として報告する。いずれもパスワード、確認コード、Firebaseトークン、UID、メールアドレス、OAuth URLのパラメータはチャット・証跡・ログに記載しない。Googleへの選択画面は撮影しない。

MANUAL-AUTH-HARNESS-06：確認対象は認証サービス＋SDKの人工的な例外の回復であり、利用者向けログイン画面や実Google障害時の完全な動作を保証しない。Calendar権限の追加・台帳変更・予約・本番運用開始は行わない。独立第三者受入30件には加算しない。検証前に実施日時、対象版、認証状態の確認方法と終了後の後片付けを記録し、結果不明の箇所は未確認として残す。

MANUAL-AUTH-HARNESS-07：2026-10-30、上記手順に沿って会社の検証用アカウントを2回選択し、人工的な失敗後の再試行から通常ログアウトまで最後まで確認できたと利用者本人が報告した。これは本人の操作報告であり、操作画面の直接観測・画像証跡はない。実Google認証と実Firebase SDKを用いたローカル専用画面での人工失敗の限定確認として扱い、自然障害・公開サイト画面・iPhoneエラーの原因や解消、第三者受入の合格には加算しない。詳細は [検証記録](../../docs/acceptance/device-readonly-2026-10-24/AUTH_INITIAL_STATE_INVESTIGATION_20261028.md) のAUTH-IOS-30〜31を参照する。
