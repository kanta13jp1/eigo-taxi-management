# AIソースレビュー方針

REVIEW-POL-01：2026-10-30、ユーザーはソースレビューの完了条件に「AIレビューと自動テスト」を採用した。従前の人によるソースレビュー必須という運用を、以下の条件に置き換える。過去の記録は、その時点の方針と状態を示す履歴として残す。

REVIEW-POL-02：対象となるコード・テスト・検査器の差分について、実装担当とは独立したAIレビューを行う。対象ファイルと現行ハッシュ、レビュー範囲、検出した問題、再現の根拠、修正・再レビューの結果、未確認事項を記録する。独立AIを人間のレビュアーとして記録しない。

REVIEW-POL-03：対象変更に適切な自動テストを実行し、実行結果、対象ソースのハッシュと検証範囲を記録する。未解決の合格阻害指摘、関連テストの失敗・未実施、証跡の欠落・不一致、レビュー対象と現在のソースの不一致がある場合は、ソースレビューを合格としない。解決後は必要な再レビューと再テストを行う。

REVIEW-POL-04：レビュー・テストの条件を満たし、ソースハッシュを更新直前に照合してから基準ハッシュを登録する。現行の `baseline` コマンドは登録済みソース全体のハッシュを記録するため、新規・変更・登録外しを含め、同時に基準が変わる全対象をレビューしてから実行する。更新後も基準・証跡・ソースの一致および厳密機械検査を確認する。機械検査のエラーだけを消すための基準更新、未レビュー状態を見逃した一括承認は禁止する。ハッシュ一致はレビューの実施や品質そのものを証明しない。

REVIEW-POL-05：2026-11-07のユーザー指示により、第三者に原30件すべてを依頼する条件は、小林さんによる[日常業務の顧客確認6件](../acceptance/CUSTOMER_ACCEPTANCE_MINIMUM_20261107.md)へ置き換えた。原AT-01〜30の技術検証は開発担当が継続し、旧第三者0/30は履歴として保持する。AIレビュー・模擬試験・開発側の確認を顧客6件の合格として計上しない。実Google連携・実機検証、本番開始判断も別である。検証用Calendarの追加は11/7にユーザー許可済みだが、実同意・配備・受入の実績はそれぞれの証跡で判断する。本番開始は禁止を維持する。

REVIEW-POL-06：本方針の制定は、現在の個別変更がレビュー済み・合格済みであることを意味しない。現状は実施したレビューの内容、関連テスト、実環境での未確認事項を別途記録し、条件を満たしたときにのみ合格とする。

REVIEW-POL-07：顧客6件のPASS記録には、実在するJSONの `mode: real-customer-check`、対象CUST-IDが一意であること、実施者が登録された顧客本人であること、タイムゾーン付き実施日時・対象版・実測値がregistryの記録と一致すること、`googleIdentityVerified: true` を要求する。demo/offline、存在しない参照、不足・不一致のある記録を拒否する。これは証跡の形式と整合の検査であり、本人認証の代替や記録された実測内容の真実性の自動証明ではない。実際の操作記録と意味のレビューも必要である。11月7日現在、顧客確認は全件未実施・0/6を維持する。[検査器の補強レビュー](reports/customer-acceptance-20261107/independent-review.json)。
