# ID・適用範囲の管理方針

## ID-POL-01 工程ID

BF（業務）、REQ（要求）、FS（設計）、TS（テスト仕様）、TASK、CODE（実装項目）、TEST（テスト対応項目）、AT/SAT（受入）、OPS（運用）、USR（利用者手順）を永続IDとします。既存IDは改番・再利用しません。1対多は配列で参照し、欠落はGAPと理由を登録します。画面IDとIF-IDも共通台帳で参照します。

原受入テストAT-01〜30を維持し、追加範囲はSAT-31〜38と分離します。新しい業務要求は根拠とともに台帳へ追加し、管理対象件数・検査仕様も明示的に改版します。

## ID-POL-02 文書・項目ID

全プロジェクトMarkdownの見出し・段落・箇条書き・表行・コードブロックをdocuments.jsonにDOC番号とITEM番号で登録します。同一内容は移動後も対応を保持します。変更した項目は新IDになり旧IDは再利用しません。履歴原本の本文に追記せず、サイドカーの行番号・ハッシュで識別します。

対象はREADME.mdとdocs配下のMarkdownです。依存ライブラリnode_modules、ツール用presentation-build、機械出力traceability/reportsは業務文書から除外します。機械レポートはハッシュ・ケースID、PowerPointはPKG番号とスライドIDで別管理します。バイナリ原本はbinary-documents.jsonで識別し、過去のPDF等を現行正本と扱いません。

## ID-POL-03 合格と整合の区別

構造検査PASSは業務合格ではありません。既存の関連テスト群は要求の全期待値を証明するものではありません。厳格検査はテスト対応の欠落で停止します。受入の合格には対象版・本人操作・結果・証跡が必要です。未検証をPASSにする変更を拒否します。

## ID-POL-04 変更と配布

生成文書の直接編集は差分検査で失敗します。登録情報から再生成してください。原資料・過去の検証記録は上書きせず、現行配布一覧から区別します。PowerPointは共通mighty-hp-v1テーマ、ロゴ・空写真・水色とオレンジ枠・Yu Gothicを使用します。配布版のファイルハッシュと検証レシートを照合します。公開・転載権の追加許諾は含みません。
