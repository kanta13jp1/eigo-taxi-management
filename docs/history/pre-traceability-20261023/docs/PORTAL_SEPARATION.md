## 画面と権限

| 入口 | ログイン後に利用できる範囲 |
| --- | --- |
| `#/admin` | 管理者本人のキーで管理画面、全生徒の送迎・チケット管理、家庭別URL・QR、Google連携設定 |
| `#/parent/<publicEntryId>` | その利用者本人のキーで、紐付いたお子様の残数、予約・取消、履歴、登録住所・連絡先だけ |
| `#/parent` | 既存利用者の共通入口。本人の家庭権限は同じ。新規配布は個別URLを優先 |
| ルート `/` | 未ログイン時の入口案内。保存済みセッションがあれば本人の入口へ移動してサーバーで再認証 |

管理者画面に利用者画面への切替を表示せず、利用者画面に管理者画面・Google設定・個別URL一覧を表示しません。役割の異なる入口ではログインを拒否します。利用者は兄弟姉妹を含め、設定済みの `studentIds` の範囲だけを扱います。管理者キーで利用者画面を確認せず、別の検証利用者で確認します。

URLだけではログインできません。個別URLとキーの組合せをGASで照合し、他家庭のキーは拒否します。GASは各リクエストでキーと家庭の権限を確認します。ブラウザーの役割値変更では管理者権限を取得できません。保存セッションも起動・再読込時に再認証します。

## 家庭・利用者を登録して配布する手順

1. 管理者が生徒を登録し、生徒IDを確認します。生徒の登録だけで保護者のアカウントは自動作成されません。
2. 設定担当者が利用者ごとに32バイト乱数のアクセスキーを用意し、SHA-256・安定した利用者ID・表示名・`role: parent`・本人に対応する `studentIds` を `AUTH_USERS_JSON` に登録します。兄弟姉妹は同じ配列へ追加できます。別の保護者には別キー・別利用者IDを使います。
3. 同じ利用者へ、認証キーとは別のランダムUUID v4を `publicEntryId` として登録します。`crypto.randomUUID()` 等で作成し、他の有効利用者と重複させません。氏名・メール・生徒IDをURLに使いません。管理者は `publicEntryId` を持ちません。
4. 管理者画面の「ご家庭の個別URL・QR」を開き、配布先の名前を確認し、URLコピーまたはQR画像保存を行います。QRはブラウザー内で生成し、外部のQR生成サービスへ送信しません。
5. 個別URL／QRと、教室のGAS接続先を対象家庭に案内します。本人専用キーは別の安全な個別経路で渡します。URL／QRにキーを埋め込みません。QR自体も無差別に掲示せず対象家庭へ配布します。
6. 本人が個別URLを開き、接続先URLと本人のキーでログインします。自家庭だけが表示されることを確認し、個別URLをブックマーク／ホーム画面に保存します。共有端末は利用後にログアウトします。

現在の画面は**登録済み利用者のURL表示・QR作成**に対応します。新規キーの発行、家庭への生徒紐付け、URLの再発行・失効は設定担当者がScript Propertiesで行います。管理画面で全処理を自動発行する仕組みではありません。

## 再発行・退会

- URLを再発行する場合は既存設定を安全に保全し、本人の `publicEntryId` だけを新UUIDへ変更して保存します。キー・役割・生徒紐付けは維持します。新URLで本人ログイン、旧URLで拒否を確認して再配布します。既に取得済みの画面情報を遠隔消去する機能ではありません。
- キー紛失・漏えい時はURL変更だけでは不十分です。古いハッシュ項目の削除、または `active: false` でキーを失効し、新しいキーへ切り替えます。退会も同様にサーバーで失効します。次の要求と再認証で拒否されます。
- 共通入口でも有効な本人キーがあれば本人の範囲で利用できます。URLの再発行はキーの失効とは区別してください。
- 既存JSONを丸ごと初期設定で上書きしないでください。`publicEntryId`・`active`・紐付け等の保全と変更後の確認が必要です。検証補助の `Prepare` は初期構築専用、日常ログインは `CopyKey` を使います。
