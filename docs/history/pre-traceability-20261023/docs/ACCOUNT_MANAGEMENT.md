# 管理者によるGoogleアカウント管理（2026-10-22）

## 担当の変更

開発者はGoogle接続と初期管理者の設定を行う。その後の利用者の追加・停止・削除、役割・生徒紐付け、家庭別URL再発行は管理者が「アカウント管理」で行う。従来資料の「変更のたびに開発者へ依頼」は、この仕様で置き換える。

## 登録・変更

1. 管理者専用ページへGoogleログインし、「アカウント管理」を開く。
2. 本人から確認したGoogleメールアドレスと表示名を入力する。管理者／保護者を選ぶ。
3. 保護者の場合は、この家庭で利用できる生徒だけを選択する。管理者権限は全生徒・アカウント管理を含むため付与先を確認する。
4. 「内容を確認」で役割・有効／停止を確認し「保存を実行」。通信エラー時は一覧を再取得して結果を確認する。
5. 保護者へ「個別URL・QR」から配布する。URLにメールアドレス・UID・キーを含めない。
6. 本人の初回Googleログインで、Google側が確認したメールと事前登録を照合し、Firebase本人UIDへ紐付く。「初回ログイン待ち」が「本人確認済み」になる。利用者や管理者がUIDを調べて入力する必要はない。

本人のメール変更は、旧登録を停止し新メールで別登録する。登録済みの別のGoogle本人UIDへ、ラベル変更だけでアクセスを移すことはしない。Googleパスワード・確認コードはGoogle画面以外へ渡さない。

## 停止・削除・再発行

- 停止：対象を編集し「利用を有効にする」を外して保存。次の通信から拒否。表示済み画面の遠隔消去ではないので共有端末はログアウトする。
- 削除：編集画面で「利用登録を削除」、対象と説明を確認して実行。このシステムの許可リストだけを削除し、Googleアカウント、Firebase認証ユーザー、生徒台帳、予約履歴は削除しない。
- 停止・削除により既存予約は自動取消されない。退会対応時は管理者が予約・チケットを別途確認する。
- 家庭URL再発行：保護者を編集して再発行にチェックし保存。「個別URL・QR」から新URLを配布。旧URLは次の通信で拒否する。本人のGoogleログインは引き続き必要。
- 自分自身の停止・削除・管理者からの降格はサーバー側でも拒否する。本人確認済みの有効管理者を最低1名残す。管理者全員のGoogleアカウント紛失等の緊急復旧は開発・導入担当が行う。
- 他管理者や初回ログイン処理と編集が競合したら、保存を拒否し一覧再取得を求める。古い画面からの上書きをしない。

## 実装と権限

GASの管理者限定API：getManagedUsers / saveManagedUser / deleteManagedUser。Google認証だけを許可し、保護者・旧キー管理者は利用不可。毎リクエスト・ロック取得後に現在の許可設定を確認する。

メール待機レコードは AUTH_GOOGLE_USERS_JSON の email: 正規化メールキーで保持。本人確認済みGoogleメールとトークンメールが一致した場合だけ、ロック内でUIDキーへ移行する。管理一覧にUIDや認証キーは返さない。既存UID登録のメール欄は未登録と表示されることがあるが、既存権限は維持される。

Googleログイン用の既存権限、検証台帳への権限、外部通信だけを利用。Googleユーザー管理の追加OAuth権限、Calendar権限、サービスアカウント秘密鍵は追加しない。
