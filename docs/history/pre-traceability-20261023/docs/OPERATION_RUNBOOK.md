## 1. システム構成とインフラアーキテクチャ

本システムは、高い耐障害性とランニングコスト0円を両立する「JAMstack + Google Cloud サーバーレス構成」を採用しています。

```
[クライアント端末 (iOS/Android/PC)]
          │ HTTPS (TLS 1.3)
          ▼
┌──────────────────────────────┐
│  フロントエンド配信層        │
│  - Firebase Hosting（検証） │
│  - 静的SPA (React + Vite)   │
└──────────────┬───────────────┘
               │ JSON / Fetch (CORS対応)
               ▼
┌──────────────────────────────┐
│  API & 永続化層              │
│  - Google Apps Script (GAS)  │
│  - Google スプレッドシート   │
│  - Google カレンダー         │
└──────────────────────────────┘
```

- **フロントエンド**: React 19, TypeScript, Tailwind CSS, Vite
- **バックエンド/DB**: Google Apps Script (GAS) Web App + Google Spreadsheet
- **カレンダー連携**: Google Calendar API (CalendarApp)

## 3. アップデート手順書（Update & Rollback）

### 3.1 通常アップデートフロー
1. ローカル開発環境で修正ブランチを作成（例: `codex/portal-update`）。既存の未コミット変更を保持します。
2. 型チェック & ビルド検証:
   ```powershell
   npm run build
   ```
3. `main` ブランチへマージしてプッシュ:
   ```powershell
   git push origin main
   ```
4. GitHub Actions により、約1分で本番環境へ自動デプロイが完了します。

### 3.2 緊急ロールバック手順

対象リリース・GAS版・設定・台帳の保存記録を確認し、直前の互換性ある版へ戻します。今回の新フロントはGAS v2と家庭別IDを前提にするため、フロントだけを旧版へ戻すと旧タブ表示に戻ります。設定だけを古いJSONで上書きしないでください。キー・role・studentIds・publicEntryId・失効状態の保全を確認します。データ更新を伴う切戻しは同時操作停止・バックアップ・台帳と予定の照合後に行い、再度権限と版を確認して再開します。

## 4. 保守運用・障害対応（Maintenance & Monitoring）

### 4.1 Google Apps Script クォータ（利用上限）管理
Googleサービスの割当と実行時間を実行アカウントで確認します。実行数・エラー・利用量を監視し、上限やタイムアウトを容量試験なしに問題なしと判断しません。認証エラー・更新結果不明時は画面と台帳を照合します。

### 4.2 データバックアップ方針
- **Googleスプレッドシートのバージョン履歴**:
  - Googleドライブ標準機能により、全編集履歴が自動保存されています。万一の誤操作時は「ファイル」➜「変更履歴」➜「変更履歴を表示」から過去の任意時点にワンクリックで復元可能です。
- **定期エクスポート（推奨）**:
  - 毎月末にスプレッドシートを「Excel形式（.xlsx）」としてローカルまたはバックアップドライブへダウンロード保存。

### 4.3 障害発生時の一次切り分けフロー
```
[不具合発生の報告]
       │
       ▼
【STEP 1】 Web画面自体が開くか？
       ├─ No ➜ Firebase Hosting / CDN の稼働状況確認
       └─ Yes ➜ 【STEP 2】へ
       │
       ▼
【STEP 2】 データ（生徒・予約）が読み込めるか？
       ├─ No ➜ Google連携URLの確認 & GASの実行ログ（Apps Script「実行数」）確認
       └─ Yes ➜ 【STEP 3】へ
       │
       ▼
【STEP 3】 カレンダー連携のみ動かないか？
       └─ Googleカレンダーの権限・カレンダーIDの存在確認
```
