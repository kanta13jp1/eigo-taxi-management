# 11月17日　古くなったブラウザー試験4件の更新

[生徒一覧の残少表示の修正](2026-11-17-student-low-ticket.md)の確認で、修正の有無にかかわらず失敗していた4件の試験（UI-06、REVIEW-UI-02・03、LOCAL-UI-07）を、現在の画面に合わせて更新した。試験だけの変更で、アプリのソース、検証サイト、正本は変更していない。顧客確認0/6件、本番開始の保留は変わらない。

## PROGRESS-20261117-TEST-01　失敗していた理由

11月12日に別のセッション（Codex）が画面を2点変えたが、試験が追従していなかった（[11月12日の記録](2026-11-12-cumulative-eighteen.md)の14・17）。

- **予約取消の確認**：ブラウザー標準の確認から、画面内のダイアログ「予約取消の確認」（「戻る」「取消を確定」）に変わった。UI-06とLOCAL-UI-07は標準の確認を待っていたため、時間切れになっていた。
- **完了ボタンの読み上げ名**：表示は「完了」のまま、読み上げ名が「送迎完了（1回消費）生徒・日付・時刻・区分」に変わった。REVIEW-UI-02は名前が「完了」だけのボタンを探していた。
- **REVIEW-UI-03**：REVIEW-UI-02が残数を2枚にした状態から10枚追加して12枚になることを確かめる試験で、02が失敗すると残数が15枚になり失敗していた。試験自体は変更せず、02の更新後に成功した。

修正前の試験が失敗していた記録は、[修正ありの実行](../../outputs/student-low-ticket-20261117/regression/local/results.json)と[修正なしの実行](../../outputs/student-low-ticket-20261117/baseline-without-fix/local/results.json)に残っている。

## PROGRESS-20261117-TEST-04　レビューの指摘への対応と残り

対応したもの：

- 改行コードがCRLFからLFに変わっていた（IR-01）。元のCRLFに戻し、入口・画面の試験を再実行して6/6件成功。
- 壊した版の具体的な変更が記録されていなかった（IR-05）。上の記録に保存した。

今回は対応していないもの（別の作業として残す）：

- **「戻る」を押しても取り消されないこと**を確かめる試験がない（IR-02）。確認ダイアログの目的そのものなので、追加する価値が高い。
- LOCAL-UI-07は、他の予約が予定中のまま残ることを確かめていない（IR-03）。
- ブラウザー標準の確認・通知を自動承諾する処理が残っており、デモデータの初期化（`GoogleSettings.tsx`）や各フォームの `alert()` は黙って通過する（IR-04）。取消の確認を標準の確認へ戻すような退行は、今回の更新で検出できる。
- 今回の4件以外にも、標準の確認を前提にした試験・手順が残っている：`run_acceptance.cjs`、`run_hosted_acceptance.cjs`、`run_all_e2e_evidence.cjs`、手動受入手順書を作る `generate_manual_uat_pdf.cjs`（「OK」を押すよう案内している）。
- 正本（r19）のソース基準・証跡は更新していない。工程横断のstrict検査はFAILの状態のまま。r19の証跡が3つの試験スクリプトの旧版を固定しているため、今回の更新で古い証跡は183件から215件、ソース基準の確認対象は6件から9件に増えた。新しい正本版へ採用するまで解消しない。

レビューを担当したAIが検査コマンドを実行した際、`docs/traceability/reports/latest.json` が上書きされた。この記録の作成後にstrict検査を実行し直して再生成した。
