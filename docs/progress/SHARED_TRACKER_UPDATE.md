# 共有残タスク表の更新手順

TRACKER-OPS-01：共有先は[小林さん向け進捗・残タスク一覧](https://docs.google.com/spreadsheets/d/1PqUq7BoBBVlPolivap0eg1UPik47vNNWphyBd0DNwvU/edit)。元台帳とは別の報告用シート。公開共有はせず、現在の個別共有を維持する。

TRACKER-OPS-02：今後この案件の検証結果が出た際は、まずローカルの検証記録へ実施日・対象版・証跡・結果・未確認範囲を保存する。その後、共有表の該当REM/AT IDを検索し、更新対象セルを再読取して必要な範囲だけ更新する。小林さんの回答・担当・期限・第三者結果を上書きしない。Excel再取込で全体を置換しない。

TRACKER-OPS-03：開発側の自動試験、開発側の実環境観測、ユーザー実施報告、独立した第三者受入を区別する。模擬APIやFirebase SDKスタブの合格で「第三者受入30件」の結果を変更しない。AT-24〜30の限定範囲確認を全体PASSにしない。

TRACKER-OPS-04：今回は既存の回答欄とは独立した「検証結果履歴」シートを追加する。履歴ID・実施日・関連ID・区分・対象・結果・証跡名・限界・次の作業を記録する。シートIDは毎回メタデータから取得し、履歴IDの重複がないことを確認する。書込後に値・数式・表示を再確認する。クラウド書込に失敗した場合はローカルに未反映として記録し、成功するまで共有表更新済みと報告しない。

TRACKER-OPS-05：シートはサイト・台帳との自動同期ではなく、許可された検証作業の結果ごとに更新する。回答待ちは待ち条件として残す。個人のメール・UID・認証情報・家庭別URL・連絡先や端末識別番号を検証結果へ転載しない。

TRACKER-OPS-06：Calendar権限の追加、本番運用開始、自動配備は行わない。Google方式は10月22日に了承済み。第三者実施者、運用用アカウント、OPEN-01〜03の回答が必要。新しい証跡がない日に過去のPASSを当日の実施結果として計上しない。
