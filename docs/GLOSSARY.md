## 📌 用語の解説とプロジェクトにおける定義・位置づけ

### Eigo Taxi Link
- **読み**: エイゴ タクシー リンク
- **カテゴリ**: システム全体
- **解説**: 個人経営の英語教室における生徒送迎を円滑化するためのWebアプリケーション。
- **本プロジェクトでの定義・位置づけ**:
  - 本リポジトリ（`eigo-taxi-management`）で開発・提供されるプロダクト全体の正式名称。
  - 送迎回数券の残数管理、予約受付、先生のGoogleカレンダー自動連携を一貫して提供し、「言った・言わない」「チケットの数え間違い」をゼロにすることを主目的とする。

---

### 先生用ダッシュボード
- **読み**: センセイヨウ ダッシュボード
- **カテゴリ**: 機能・UI
- **解説**: 管理者である英語教室の先生が日常業務で利用するメイン画面。
- **本プロジェクトでの定義・位置づけ**:
  - フロントエンドの [`src/components/TeacherDashboard.tsx`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/src/components/TeacherDashboard.tsx) に該当。
  - 「本日の送迎予定一覧（タイムライン）」「生徒台帳＆チケット残数一覧」「チケット追加チャージ」「送迎完了操作」などを集約。

---

### 生徒・保護者用ポータル
- **読み**: セイト・ホゴシャヨウ ポータル
- **カテゴリ**: 機能・UI
- **解説**: スマートフォン閲覧に最適化された、保護者・生徒向けのセルフサービス画面。
- **本プロジェクトでの定義・位置づけ**:
  - フロントエンドの [`src/components/ParentPortal.tsx`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/src/components/ParentPortal.tsx) に該当。
  - ログイン等の複雑な認証を排し、URLアクセスや生徒選択から即座に「チケット残数確認」「送迎予約」「キャンセル」が行える簡易ポータル。

---

### 送迎チケット / 残チケット数
- **読み**: ソウゲイチケット / ザンチケットスウ
- **カテゴリ**: 業務・データ
- **解説**: 送迎サービスを利用するための前払い回数券。
- **本プロジェクトでの定義・位置づけ**:
  - データモデル上の `remainingTickets` および `ticketsHistory`（チケット購入・チャージ履歴）に関連。
  - 送迎完了時に1回（または往復等のルールに応じて）消費される。
  - 残数が少なくなった生徒（残り1回以下や0回）はダッシュボード上で視覚的警告表示（バッジハイライト）される。

---

### 送迎区分（お迎え / 送り / 往復）
- **読み**: ソウゲイクブン（オムカエ / オクリ / オウフク）
- **カテゴリ**: 業務・データ
- **解説**: 送迎の方向性・運行パターン。
- **本プロジェクトでの定義・位置づけ**:
  - `RideType`（`'pickup'` | `'dropoff'` | `'roundtrip'`）として定義。
  - 予約時に入力され、先生側のタイムラインやGoogleカレンダーの件名・説明欄に反映される。

---

### 送迎完了処理
- **読み**: ソウゲイカンリョウショリ
- **カテゴリ**: 業務・システム
- **解説**: 実際に運行が完了したことをシステムに記録するアクション。
- **本プロジェクトでの定義・位置づけ**:
  - 予約時点ではチケットを消費せず、先生が現場または送迎後に「送迎完了（1回消費）」ボタンを押したタイミングで、対象生徒の残チケットをマイナス1する仕様。
  - 誤引き落としや直前キャンセルによるトラブルを防ぐ設計上のキーポイント。

---

### 生徒台帳
- **読み**: セイトダイチョウ
- **カテゴリ**: 業務・データ
- **解説**: 教室に通う生徒の基本情報、送迎先住所、保護者連絡先などを集約したマスタ。
- **本プロジェクトでの定義・位置づけ**:
  - Googleスプレッドシートの「生徒台帳」シートおよび `Student` 型に該当。
  - 生徒名、学年/年齢、デフォルトの送迎場所（Googleマップリンク連携用）、緊急連絡先、送迎時の特記事項（アレルギー、待ち合わせルールなど）を保持する。

---

### Google連携 (GAS / スプレッドシート / カレンダー)
- **読み**: グーグルレンケイ (ガス / スプレッドシート / カレンダー)
- **カテゴリ**: インフラ・バックエンド
- **解説**: Google Workspace / Google アカウントの標準機能をバックエンドとして活用する仕組み。
- **本プロジェクトでの定義・位置づけ**:
  - バックエンドサーバーや有料DBを構築せず、[`gas/Code.gs`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/gas/Code.gs) を Google Apps Script のウェブアプリとしてデプロイ。
  - スプレッドシートをデータベース、カレンダーを予定通知・管理ハブとして利用することで、月額インフラ費用0円で運用可能にしている。

---

### LocalStorageモックエンジン
- **読み**: ローカルストレージ モックエンジン
- **カテゴリ**: アーキテクチャ
- **解説**: ブラウザのローカルストレージを利用して擬似的にバックエンド動作を再現する開発・デモ用機構。
- **本プロジェクトでの定義・位置づけ**:
  - [`src/services/api.ts`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/src/services/api.ts) 内に実装。
  - GASのWebアプリURLが設定されていない状態でも、初期ダミーデータを投入し、即座に画面操作・動作確認・テストをスタンドアロンで実行できるようにしている。

### 正式納品
- **読み**: セイシキノウヒン
- **カテゴリ**: プロジェクト管理・リリース
- **解説**: 受入テスト（UAT）等の検証完了後、成果物一式（プログラム、環境、ドキュメント類）を発注者・利用者に引き渡し、検収・受領手続きを正式に完了させるプロセス。
- **本プロジェクトでの定義・位置づけ**:
  - 英語教室の運営者（Mauro様、Brenda様）に対し、本システム「Mauro & Brenda Taxi Link（Eigo Taxi Link）v1.0 (GA)」および関連成果物を正式に引き渡すマイルストーン。
  - [`docs/DELIVERY_CHECKLIST.md`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/docs/DELIVERY_CHECKLIST.md) に規定された納品構成（プログラム一式、Google Apps Script、Webアプリ本番URL、スプレッドシート、Googleカレンダー、管理者マニュアル、保護者向け利用ガイド、運用手順書、UAT完了証跡等）の検収完了をもって成立する。

### リリース
- **読み**: リリース
- **カテゴリ**: 運用・CI/CD・デリバリー
- **解説**: 開発・テストが完了したソフトウェアや新機能を本番環境に展開し、利用者がアクセス・利用できる状態にする作業。
- **本プロジェクトでの定義・位置づけ**:
  - 本システムにおけるリリースは、**①フロントエンド（Webアプリ）の自動デプロイ** と **②バックエンド（GAS/スプレッドシート）の本番公開・接続** の2段階で構成される。
  - **フロントエンド**: GitHub Actions ワークフロー（[`.github/workflows/deploy.yml`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/.github/workflows/deploy.yml)）により、`main` ブランチへのプッシュ・マージをトリガーとして GitHub Pages へ自動ビルド＆公開される。
  - **バックエンド/DB**: 教室用のGoogleアカウント上で [`gas/Code.gs`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/gas/Code.gs) をウェブアプリとして新規デプロイし、発行されたURLを管理画面（`GoogleSettings`）に登録・疎通確認（スモークテスト）を行う手順を指す（詳細は [`docs/OPERATION_RUNBOOK.md`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/docs/OPERATION_RUNBOOK.md) 参照）。

### GA (General Availability)
- **読み**: ジーエー / ジェネラル アベイラビリティ
- **カテゴリ**: プロジェクト管理・リリースサイクル
- **解説**: ソフトウェア開発において、先行試験版（Alpha/Beta）やリリース候補版（RC）を経て、全ユーザーに向けて本番提供される「正式版・一般提供開始」の状態。
- **本プロジェクトでの定義・位置づけ**:
  - 本システム「Mauro & Brenda Taxi Link（Eigo Taxi Link）」の正式商用稼働バージョン（**v1.0 (GA)**）を指す。
  - すべての機能受入試験（UAT: TC-G01〜G06、TC-P01〜P09、TC-T01〜T08等）を合格し、教室運営者（Mauro様、Brenda様）の実運用に供する品質基準を満たした状態（「GA Ready」）を示す。
  - 保守運用手順書（[`docs/OPERATION_RUNBOOK.md`](file:///c:/Users/kanta/GitHub/eigo-taxi-management/docs/OPERATION_RUNBOOK.md)）において、納品後の無償不具合対応を行う「QA対応保証期間（30日間）」の起算点として定義されている。
  - ※Google技術スタックを採用しているが、本プロジェクトの文脈においては「Google Analytics」ではなく「一般提供（General Availability）」の意味で使用される。
