# Mauro & Brenda Taxi Link 保守運用・リリース・アップデート手順書（SOP）

**対象読者**: 株式会社MightyLINK 開発・インフラ・保守運用チーム  
**システム名**: 英語教室 送迎チケット管理システム（Mauro & Brenda Taxi Link）  
**バージョン**: 1.0 (GA Ready)

---

## 1. システム構成とインフラアーキテクチャ

本システムは、高い耐障害性とランニングコスト0円を両立する「JAMstack + Google Cloud サーバーレス構成」を採用しています。

```
[クライアント端末 (iOS/Android/PC)]
          │ HTTPS (TLS 1.3)
          ▼
┌──────────────────────────────┐
│  フロントエンド配信層        │
│  - GitHub Pages / Cloudflare │
│  - 静的SPA (React + Vite)   │
└──────────────┬───────────────┘
               │ JSON / Fetch (CORS対応)
               ▼
┌──────────────────────────────┐
│  API & 永続化層              │
│  - Google Apps Script (GAS)  │
│  - Google スプレッドシート   │
│  - Google カレンダー         │
└──────────────────────────────┘
```

- **フロントエンド**: React 18, TypeScript, Tailwind CSS, Vite
- **バックエンド/DB**: Google Apps Script (GAS) Web App + Google Spreadsheet
- **カレンダー連携**: Google Calendar API (CalendarApp)

## 2. 本番リリース手順書（Release Procedure）

### 2.1 事前準備
1. **お客様専用Googleアカウントの確認**:
   - `taxi@...` 等の教室共用Googleアカウントが用意されていることを確認。
2. **既存生徒データの受領**:
   - 生徒氏名、保護者氏名、連絡先電話番号、送迎先住所、現在残チケット数をExcel/CSV等で受領。

### 2.2 本番スプレッドシート & GASの構築
1. 共用Googleアカウントで新規スプレッドシートを作成（タイトル: `Mauro & Brenda 送迎管理データベース`）。
2. 「拡張機能」➜「Apps Script」を開き、`src/components/GoogleSettings.tsx` 内の最新GASコードを `Code.gs` に貼り付け。
3. `initSpreadsheet` を実行し、承認を許可（3シート自動生成）。
4. 「生徒台帳」シートに受領した初期生徒マスタを転記。
5. 「デプロイ」➜「新しいデプロイ」➜「ウェブアプリ（自分として実行 / アクセス: 全員）」でデプロイし、本番WebアプリURLを発行。

### 2.3 フロントエンドのデプロイ
1. リポジトリの `main` ブランチにタグを付与（例: `git tag v1.0.0 && git push origin v1.0.0`）。
2. GitHub Actions によりビルド & GitHub Pages（またはCloudflare Pages）へ自動反映。
3. Webアプリ画面を開き、「⚙ Google連携」タブで本番GAS WebアプリURLを保存。

### 2.4 リリース前スモークテスト（3分チェック）
- [ ] 生徒一覧に本番データが表示されるか
- [ ] テスト用送迎予約が1件登録でき、スプレッドシートおよびGoogleカレンダーに反映されるか
- [ ] テスト予約をキャンセルし、スプレッドシートが `cancelled` になりカレンダーから消えるか
- [ ] テスト行をスプレッドシートから手動削除（クリーンアップ）

## 3. アップデート手順書（Update & Rollback）

### 3.1 通常アップデートフロー
1. ローカル開発環境で修正ブランチを作成（`feature/xxx` または `fix/xxx`）。
2. 型チェック & ビルド検証:
   ```powershell
   npm run build
   ```
3. `main` ブランチへマージしてプッシュ:
   ```powershell
   git push origin main
   ```
4. GitHub Actions により、約1分で本番環境へ自動デプロイが完了します。

### 3.2 緊急ロールバック手順
万一本番反映後に重大な不具合が発生した場合、直前の安定コミットへ即時ロールバックします：
```powershell
# 直前の正常コミットIDを指定して強制ロールバック
git revert HEAD --no-edit
git push origin main
```

## 4. 保守運用・障害対応（Maintenance & Monitoring）

### 4.1 Google Apps Script クォータ（利用上限）管理
Google Workspace / 無料Gmailアカウントには以下の1日あたりクォータ制限が存在しますが、小規模教室の運用規模（送迎数十件/日）では上限の1%未満であり、通常枯渇することはありません：
- **Calendar 作成・削除**: 1日あたり 5,000回（十分な余裕あり）
- **URL Fetch / トリガー実行時間**: 1日あたり 90分（API応答は数十ミリ秒のため問題なし）

### 4.2 データバックアップ方針
- **Googleスプレッドシートのバージョン履歴**:
  - Googleドライブ標準機能により、全編集履歴が自動保存されています。万一の誤操作時は「ファイル」➜「変更履歴」➜「変更履歴を表示」から過去の任意時点にワンクリックで復元可能です。
- **定期エクスポート（推奨）**:
  - 毎月末にスプレッドシートを「Excel形式（.xlsx）」としてローカルまたはバックアップドライブへダウンロード保存。

### 4.3 障害発生時の一次切り分けフロー
```
[不具合発生の報告]
       │
       ▼
【STEP 1】 Web画面自体が開くか？
       ├─ No ➜ GitHub Pages / CDN の稼働状況確認
       └─ Yes ➜ 【STEP 2】へ
       │
       ▼
【STEP 2】 データ（生徒・予約）が読み込めるか？
       ├─ No ➜ Google連携URLの確認 & GASの実行ログ（Apps Script「実行数」）確認
       └─ Yes ➜ 【STEP 3】へ
       │
       ▼
【STEP 3】 カレンダー連携のみ動かないか？
       └─ Googleカレンダーの権限・カレンダーIDの存在確認
```

## 5. QA対応期間とサポート体制

- **QA対応期間**: GAリリース日より **30日間**
- **対応内容**:
  - 仕様書に準拠していない動作、計算不具合、連携エラーの無償改修
  - 先生方・管理者様からの操作問い合わせへの一次回答
- **受付窓口**:
  - 株式会社MightyLINK 開発保守窓口（Slack / メール / チャットワーク）
  - 平日 10:00 〜 19:00（重大障害時は即時対応）
