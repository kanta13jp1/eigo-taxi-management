# Gmail以外のメールを使ったGoogleログイン：運用補足

ACC-MAIL-01：この資料は `FS-31/32`、`OPS-31/32`、`USR-31/32` の補足です。現在のシステムはGoogleアカウントによる本人ログインと利用登録を必要とします。メールアドレスが `@gmail.com` であることは必須ではなく、会社や学校の独自ドメインのメールアドレスを用いるGoogleアカウントも候補です。メールアドレスを持っているだけではログインできません。

ACC-MAIL-02：メールがGoogleアカウントとして使えるか、ご本人に確認いただきます。アカウントがなければ、本人が既存メールを用いてGoogleアカウントを作成し、メールの確認コードを本人の受信箱で確認する方法があります。既存アカウントの利用や別のGoogleアカウントを選ぶ方法もあります。[Google公式：Googleアカウントの作成](https://support.google.com/accounts/answer/27441?hl=ja)。パスワード、確認コード、認証情報を管理者や開発者へ伝える必要はありません。会社・学校が管理するメールについては、その組織の利用方針も確認してください。

ACC-MAIL-03：管理者は、本人に確認したGoogleアカウントを管理画面の「アカウント管理」で本人の役割とともに事前登録します。保護者の場合は対象の生徒を紐付けます。初回は本人がGoogleでログインし、認証されたメールが事前登録の有効なメールと一致すると本人の識別情報に紐付けられます。GASはGoogleプロバイダーと確認済みメールを検証し、`@gmail.com` に限定しません。Googleアカウントの予備メールとGoogleログイン時に返されるメールは同じとは限らないため、登録するメールを本人と照合し、初回ログインで確認します。紐付け後のアクセスは有効状態と権限も確認されます。

ACC-MAIL-04：本番でスプレッドシートやカレンダーを管理する教室側の運用用Googleアカウントと、先生・保護者それぞれのログイン用アカウントは用途が異なります。同一にするかどうかを前提にせず、所有・管理担当とアクセス権を別途確認します。運用環境の準備や権限追加は、本資料の作成だけでは完了しません。

ACC-MAIL-05：2026-10-30に共有された先生の独自ドメインのアドレスがGoogleアカウントとして使えるか、Google側で認証されたメールが登録するメールと一致するか、実際にログインできるかは未確認です。利用者の氏名・アドレス、確認コード、個別URL、認証情報を共有用検証記録に記載しません。実ログインは本人確認・適切な利用登録後に実施し、結果と未確認範囲を記録します。
