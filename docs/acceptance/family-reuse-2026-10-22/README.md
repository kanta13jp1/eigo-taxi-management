# 3アカウントの役割切替による家庭A/B実検証

ユーザー承認済み：会社アカウントは管理者として維持。個人の管理者2人目を家庭Aへ一時変更し、別個人アカウントを家庭Bに登録。検証後は家庭Aを元の管理者2人目へ戻し、家庭B登録を削除する。Google/Firebaseのアカウント自体は削除しない。

家庭AはSTU-001、家庭BはSTU-002の架空生徒を使用。会社管理者のセッションを保持して復元する。個人メール・UID・トークンは公開証跡に含めない。変更前の非公開設定コピーを保全済み。本人UIDに紐付く家庭Aは役割変更、家庭Bはメール事前登録→初回Google本人紐付けを実測予定。

現在：登録準備中。ログイン・自家庭表示・他家庭URL拒否・管理者入口拒否・再読込・ログアウト・復元を証跡確認後にのみPASSとする。復元完了前に作業全体を完了扱いしない。

Calendar権限追加・Calendar操作・予約/取消/チケット更新・本番運用開始は行わない。3アカウントの時分割検証であり、管理者2名＋保護者2家庭を同時に確認したとは扱わない。AT26全体・AT24〜30・第三者30件の合格は別判定。

## 家庭登録完了・家庭A本人選択待ち
会社管理者の再認証済みセッションから、管理画面で家庭BをSTU-002へ事前登録。管理者2人目を家庭A・STU-001へ一時変更し、専用URLを取得した。会社管理者1名は維持。家庭AのGoogle選択画面を開き、本人の手動選択待ち。復元はまだ未実施で、検証終了後に管理者2人目へ戻し家庭B登録を削除する。進行状況は[phase.json](phase.json)。公開受入のPASSはまだ付けない。PowerPointの検証済み最新版はv20を維持し、家庭検証結果確定後に改版する。

## 家庭Aの本人表示・再読込を確認
公開検証サイトで検証家庭Aとして実Googleログイン。STU-001に対応する架空生徒1名・残7回・取消履歴2件だけを表示し、STU-002・追加検証生徒・管理者メニューは表示されない。再読込後も一致：[表示結果](family-a-display-results.json)／[画面](family-a-reloaded.png)。家庭BのURLへ同じタブで移動するとログイン画面となり、他家庭データは非表示：[画面](family-a-other-url-blocked.png)。さらに家庭BのURLで家庭A本人を選択して明示的拒否を確認するため、Googleの手動選択待ち。管理者入口拒否・家庭B・復元は未完了。

## 家庭A本人による家庭B URLログインを拒否
家庭B専用URLで家庭A本人をGoogle認証した後、『この個別URLは利用できません。教室に最新URLを確認してください』を公開画面で確認。他家庭の生徒・台帳・管理メニューは非表示。[証跡](family-a-authenticated-other-family-denied.png)。家庭A→家庭Bの本人認証付き拒否はPASS。家庭Bの本人ログインへ進む。復元は検証完了後に行うため、現在は一時的な役割を維持。

## 家庭Bの初回Googleログイン・表示・再読込を確認

## 最新結果：相互拒否と元の管理者2名への復元を確認
