# 小林さん用　送迎の確認手順

検証サイトで、保護者の予約から先生のチケット管理までを6件ご確認ください。対象は開発担当がご用意する架空の家庭です。実際の送迎や支払いは発生しません。

## 開始前に開発担当がそろえるもの

- 開発担当が小林さんの会社Googleアカウントを検証担当として事前登録します。ご本人は同じアカウントで、固定の家庭用URLと管理者用URLを使い分けます。操作中に開発担当が役割を変える必要はありません。通常の管理者・保護者とは別の検証用登録で、指定した検証生徒だけを扱います。
- 指定の架空生徒1名、開始残数5枚、固定した日付の「CUST-04 完了確認用・片道」「CUST-04 完了確認用・往復」の予約各1件と模擬実績表。日付が過ぎても「送迎スケジュール一覧」から同じ予約を開きます。
- 検証用の公開版番号、検証専用カレンダーの閲覧方法。開発担当がカレンダーの権限・接続先・予約と取消の動作を事前確認してからご案内します。実在の家庭や会社の業務予定には触れません。

## 操作と記録

開始の準備完了案内を受けたら、ご都合のよい時に次の順で進めてください。画面を変えるときは、いまの画面からログアウトし、もう一方の固定URLを開いて同じGoogleアカウントでログインします。日程連絡や開発担当への切替依頼は不要です。

| 使う画面 | 小林さんが確認すること |
| --- | --- |
| 保護者（1回目） | CUST-01～03。架空生徒と残数5枚を確認し、予約1件を登録してカレンダーと照合した後、その予約を取り消します。 |
| 管理者（1回目） | CUST-04。準備済みの片道・往復を順に完了し、残数が5→4→2枚となることを確認します。 |
| 保護者（2回目） | CUST-05の前半。残り2枚でMauro・Brendaへの連絡案内を読みます。 |
| 管理者（2回目） | CUST-05で10枚・検証用0円を登録して12枚を確認。続けてCUST-06の管理者分としてログアウトし、再読込して台帳が見えないことを記録します。 |
| 保護者（3回目） | CUST-05の家庭側で12枚と案内の消失を確認。CUST-06の家庭分としてログアウトし、再読込して台帳が見えないことを記録します。 |

## 途中で中断・再開する場合

共有表に実施済みの項目・最後の残数・対象予約の日時を記録し、ログアウトしてください。再開時は、最後に記録した画面のURLから入り直し、同じ生徒・予約・残数を確認して未実施の手順だけを進めます。最初から予約やチケット追加を繰り返さないでください。完了済みの予約は再度完了にしません。開始時5枚→片道後4枚→往復後2枚→10枚追加後12枚が目印です。記録と現在の値が異なる場合は「要確認」で止め、通常の問い合わせとしてお知らせください。異常時の調査まで不要になる仕組みではありません。

各項目で見えた結果と時刻を末尾の記録欄に記入してください。該当する役割や画面を用意できない場合は「未実施」、期待と異なる場合は「要確認」として、その時点の画面を開発担当に伝えてください。繰り返し送信せず、その結果に依存する手順は待ってください。画像の代わりに画面名と前後の値を記したメモでも確認できます。

<a id="CUST-01"></a>
### CUST-01　本人のGoogleログインと家庭の残数

**小林さんの操作（保護者）**　家庭専用の固定検証URLを開き、「Googleでログイン」で登録済みの本人アカウントを選ぶ。子どもの選択欄とチケット残高を見る。初めての開始時は5枚、途中再開時は共有表に記録した最後の残数と照合する。

**画面で確かめる結果**　表示されるのは割り当てた検証生徒だけで、初期状態は5枚。別の家庭のお子様は選択肢に出ない。

**記録すること**　表示されたテスト用のお子様名と残数、ほかの家庭名の有無。

対応する開発側の確認項目　[AT-01](06_ACCEPTANCE_TEST_SPEC.md#AT-01)、[AT-03](06_ACCEPTANCE_TEST_SPEC.md#AT-03)、[AT-20](06_ACCEPTANCE_TEST_SPEC.md#AT-20)。

<a id="CUST-02"></a>
### CUST-02　1回分の予約と検証カレンダーの照合

**小林さんの操作（保護者・検証カレンダー閲覧）**　「送迎の予約を申し込む」から、実施日または翌日の任意の時刻、「お迎え」、登録済みの架空の乗車場所、メモ「CUST-02 取消確認用」を指定し「送迎予定を登録する」を1回押す。「現在予約中の送迎」と検証カレンダーの同日の予定を開く。CUST-04の事前準備した2件には触れない。

**画面で確かめる結果**　事前準備した完了確認用2件とは別に、取消確認用が1件増える（初期2件→3件）。生徒・日付・時刻・場所がカレンダーと一致する。繰返しのない1回分の予約で、チケットは5枚のまま。

**記録すること**　テスト名・日時・場所、予約件数、カレンダーの予定説明にある予約ID、残数。

対応する開発側の確認項目　[AT-06](06_ACCEPTANCE_TEST_SPEC.md#AT-06)、[AT-24](06_ACCEPTANCE_TEST_SPEC.md#AT-24)。

<a id="CUST-03"></a>
### CUST-03　予約を取り消して残数を確認

**小林さんの操作（保護者・検証カレンダー閲覧）**　CUST-02で自分が作成した取消確認用の予約だけを選び、「キャンセル」を押す。確認画面で生徒・日時・送迎区分・送迎先・備考を照合し、「取消を確定」を押す。家庭画面と検証カレンダーを再読込する。事前準備したCUST-04の2件は取り消さない。

**画面で確かめる結果**　自分で作成した取消確認用だけが「現在予約中の送迎」とカレンダーから消える（3件→2件）。完了確認用の2件は残る。取消前も取消後もチケットは5枚。

**記録すること**　取り消した予約の日時、両画面で確認した結果、前後の残数。

対応する開発側の確認項目　[AT-10](06_ACCEPTANCE_TEST_SPEC.md#AT-10)、[AT-25](06_ACCEPTANCE_TEST_SPEC.md#AT-25)。

<a id="CUST-04"></a>
### CUST-04　送迎完了で片道1枚・往復2枚を消費

**小林さんの操作（管理者）**　家庭画面からログアウトし、固定の管理者URLに同じGoogleアカウントでログインする。「送迎スケジュール一覧」で、固定日の模擬実績表に対応する乗車場所に「CUST-04 完了用A・片道」「CUST-04 完了用B・往復」と表示された予約の2件を特定する。日付が過ぎていても同じ一覧を使う。未完了の片道を「完了」にして残数を確認し、次に未完了の往復を同じように完了する。途中再開時は完了済みを繰り返さない。

**画面で確かめる結果**　準備時に残数5枚。片道の完了後は4枚、往復の完了後は2枚。2件とも完了として表示される。

**記録すること**　片道・往復のテスト用の日時、各完了表示と5→4→2の実測値。

対応する開発側の確認項目　[AT-13](06_ACCEPTANCE_TEST_SPEC.md#AT-13)、[AT-14](06_ACCEPTANCE_TEST_SPEC.md#AT-14)。

<a id="CUST-05"></a>
### CUST-05　残少のお知らせとチケット追加

**小林さんの操作（保護者・管理者）**　管理者画面からログアウトし、家庭用の同じ固定URLで残り2枚の案内文を読む。ログアウトして管理者用の固定URLへ入り、同じ検証生徒の「チケット追加」で10枚・受取金額0円を1回だけ登録する。ログアウト・再読込後に管理者の台帳が非表示であることをCUST-06の管理者分へ記録する。家庭用固定URLへ入り直して12枚と案内の消失を確認する。追加済みなら再追加しない。

**画面で確かめる結果**　残り2枚でMauro・Brendaに連絡する案内が表示される。追加後は両方の画面で12枚となり、家庭画面の残少案内が消える。

**記録すること**　連絡先の表示、追加した枚数・検証用金額、追加前後の残数。実際の支払いと連絡は不要。

対応する開発側の確認項目　[AT-04](06_ACCEPTANCE_TEST_SPEC.md#AT-04)、[AT-05](06_ACCEPTANCE_TEST_SPEC.md#AT-05)。

<a id="CUST-06"></a>
### CUST-06　ログアウト後に台帳が見えないことを確認

**小林さんの操作（保護者・管理者）**　今回使った家庭画面・管理者画面で、それぞれログアウトする。同じURLを開き直すか再読込し、ログイン前の表示を確かめる。

**画面で確かめる結果**　両方ともログイン画面に戻り、氏名・チケット残数・予約履歴・生徒台帳が表示されない。

**記録すること**　両方の役割について、再読込後に表示された画面名と台帳の表示有無。

対応する開発側の確認項目　[AT-01](06_ACCEPTANCE_TEST_SPEC.md#AT-01)、[AT-19](06_ACCEPTANCE_TEST_SPEC.md#AT-19)、[AT-26](06_ACCEPTANCE_TEST_SPEC.md#AT-26)。
