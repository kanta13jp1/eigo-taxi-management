## ASYNC-02　検証担当のアクセス範囲

保存する役割 `reviewer` は架空データ専用の検証台帳でのみ使用する。Script Propertiesの `ACCEPTANCE_REVIEW_SPREADSHEET_ID` と実際の結合台帳IDが完全一致しない場合は有効化・利用を拒否する。Google本人確認後、開いた画面に対応する公開roleと `reviewOnly` をサーバーが決める。

管理者画面でも、管理者が割り当てた検証生徒だけを取得・予約・取消・完了・チケット追加できる。生徒の新規登録、アカウント一覧・変更・削除、他の家庭の個別URL一覧は拒否する。家庭画面からの完了・追加も拒否する。ログイン後に停止・対象生徒・役割・検証台帳設定が変わった場合は、次の通信と更新ロック内で再判定する。URLの変更だけでは通常アカウントの権限は増えない。

台帳に実データを混在させない。割当生徒の設定自体は管理者の確認事項で、IDだけでは架空データの由来を証明しない。Calendarの閲覧共有はアプリの生徒範囲とは別で、共有するのは架空予定専用のカレンダーだけにする。

## ASYNC-04　中断・別日再開

共有表に終えた項目、最後の残数、対象予約の日時と状態を記入してログアウトする。再開時は保存されている台帳を読み直し、次の状態と共有表を照合して未実施だけ進める。

| 再取得した状態 | 次の操作 |
| --- | --- |
| 5枚・完了用2件が予定中 | 自分で作成した取消確認用が表示中ならその1件を取消。取消済みの履歴・自分の記録があれば再作成せず次へ。未作成と確認できた場合だけ1件を作成。不明なら止める。予約・取消の確認後に片道完了へ |
| 4枚・片道だけ完了 | 往復を完了 |
| 2枚・両方完了 | 家庭側で残少案内を読み、その後10枚・0円を1回追加 |
| 12枚・両方完了・共有表に10枚の追加記録あり | 追加済み。再追加せず家庭側の表示とログアウト確認へ |
| 記録と不一致、または操作結果不明 | 「要確認」として止め、表示内容・日時を連絡 |

ブラウザーを閉じた後や別端末では、通信の再送識別子が引き継がれない場合がある。同じ予約の追加・購入を最初から繰り返す手順にはしない。自動リセットも行わない。本人が見なかった画面を後から合格にはしない。通常の実施に立会いは不要だが、異常が起きた場合の調査は別途必要である。
